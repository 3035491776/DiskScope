# v0.2.0 — Cleanup Center

## Real-world scan metadata compatibility hotfix

Windows 文件系统可能返回能正常读取大小、但无法由 Python 转换为日期的极端修改时间。扫描器现在把这种情况记录为有界的 `INVALID_FILE_METADATA` 警告：文件数量、逻辑大小和目录聚合仍正常计入，文件仍可参与按大小 Top-K；时间显示为不可用，并且不会参与当前用户 Temp 的 oldest 选择。`skipped_count` 不会增加，扫描覆盖标记为 limited，已完成结果仍可保存为 schema v7 Snapshot。

只局部捕获 `OSError`、`OverflowError` 和 `ValueError` 的时间转换失败。根目录不可用、未处理的 I/O 错误和内部程序错误仍使扫描失败；任务级失败日志使用完整 traceback，并包含 scan ID、scope、root label、异常类型和消息。该修复不改变 Cleanup Center 授权、M8 单 worker 扫描结构、Top-K 大小排序或 Temp 10,000 hard cap。

## Product rationale

v0.1.1 解决了主要结果“看不懂”的问题，但真实用户完成扫描后仍不知道下一步。v0.2.0 在不改变 DiskScope“诊断优先”身份的前提下，增加“清理空间”闭环：扫描、分类、选择、实时复核、移入回收站、解释逐项结果。

## Three-tier model

- `SAFE_ACTIONABLE`（可处理）：只来自现有 `ExecutionPolicyEngine` 的 `eligible_for_recycle`。`USER_TEMP_STALE_FILE_V1`、30 天、普通文件、当前用户 Temp、低风险、高置信和 denylist 全部保持。
- `REVIEW_REQUIRED`（建议手动检查）：由独立 `ManualReviewPolicy` 授权，只覆盖当前用户 profile 下 Downloads、Desktop、Documents、Videos、Pictures 和 Music 中的普通文件。不会修改或冒充现有安全策略。
- `DO_NOT_TOUCH`（不建议处理）：系统/程序位置、危险类型、目录、reparse、非当前用户位置、未知或无法证明安全的项目。任何执行路线均不得覆盖。

分类只决定用户界面分组，不是执行授权。Prepare 和 Execute 都重新调用相应授权策略，客户端不能提交路径、classification 或任意执行目标。

## Safe batch flow

客户端最多提交 200 个服务器生成的 item ID。Prepare 逐项加载当前最新扫描记录、执行 live metadata/reparse/volume/type/identity 检查，并签发绑定 item set、scope、decision digest、进程 session 与 90 秒有效期的单次 batch token。Execute 再逐项检查并顺序调用 Windows `IFileOperation` + `FOFX_RECYCLEONDELETE`。没有永久删除回退。

## Manual review flow

人工检查项目不默认选择、不提供全选，并要求额外勾选“我已经检查过所选文件，并确认不再需要”。该确认只允许进入独立 review prepare；safe 项不能借 review 路线绕过策略，review 项也不能进入 safe 路线。

## Hard deny boundaries

Windows、Program Files、Program Files (x86)、ProgramData、Recovery、System Volume Information、`$Recycle.Bin`、非当前用户 profile、目录、symlink、junction、reparse、special file 和危险扩展名一律拒绝。未知状态 fail closed。

## TOCTOU and partial success

Prepare 保存 size、mtime、ctime、mode、volume/device、file identity 和 Windows attributes 指纹。Execute 再读取并要求与 Prepare 完全一致。一个项目变化、消失、被占用或无权限时只跳过/失败该项目，其余项目继续；已成功进入回收站的项目不会因后续失败回滚。

## Recycle Bin semantics

界面只描述“移入 Windows 回收站的文件大小”，从不声称已经释放等量空间。DiskScope 不查看、恢复或自动清空回收站。

## DB migration

SQLite schema 从 v6 原位、additive 升级到 v7，新增 `cleanup_batches` 与 `cleanup_batch_items`。旧 Snapshot、History、Candidates、单文件审计与 controlled probes 不重建、不清空。batch token 绑定当前进程 session，重启后失效；审计仍可读取。

## Friend-test plan

第二轮重点验证扫描后行动入口、三类差异、safe 批量选择、review 逐项选择和额外确认、部分成功解释，以及用户是否理解“回收站而非永久删除”。清单见 `docs/friend-test-checklist.md`。

## Backlog

不实现目录清理、永久删除、自动清空/管理回收站、Windows/Program Files 清理、系统转储、应用缓存自动清理、MFT/USN、撤销 UI 或 installer。未来可评估应用专属清理适配器、回收站集成与可选安装器。
