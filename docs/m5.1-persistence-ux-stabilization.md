# M5.1：结果恢复与扫描体验稳定化

M5.1 修复重启后总览、空间分析和大文件与目录依赖内存任务的问题，并完善运行中资源指标、长路径布局与覆盖说明。扫描器仍是单枚举 worker、元数据只读、不跟随重解析点、不跨卷；本阶段没有清理执行能力，也没有重扫 C:。

## 结果来源

`ResultResolver` 按固定 scope 分别选择当前进程中最近的 `completed` 结果，再选择 SQLite 中最新的 `completed` 快照；两者都不存在时返回 `none`。`cancelled` 和 `failed` 不取代成功结果。`GET /api/v1/results/latest` 明确给出 `source_type`、`result_id`、`snapshot_id`、`scope_key`、`completed_at`、`coverage`、摘要和存储状态；目录层级与 Top 文件/目录分别按来源读取。Snapshot 路径由 SQLite 查询，`ORDER BY subtree_bytes DESC LIMIT N` 在数据库执行，不把完整目录树送入浏览器。三个页面共用这份来源标识并展示扫描时间；新的扫描运行时仍展示其任务状态，浏览区注明旧的已完成结果。

Snapshot 是历史元数据的独立只读模型，不会伪装成完整的实时 `ScanResult`。未保存的字段显示不可用。**Historical metadata is not execution authority.** 任何未来真实操作都必须重新验证目标当前状态；M5.1 不实现这些操作。数据库不可用时结果查询返回明确的不可用状态，扫描器不会因此崩溃；已完成的内存结果仍可浏览。

## 资源指标

运行中按至少 1 秒间隔观测 DiskScope 后端进程自身。状态接口可返回当前 RSS、扫描期间观测峰值 RSS、累计进程 CPU 秒数、任务耗时、文件速率及可取得的进程 I/O 差值。峰值取先前峰值与当前 RSS 的最大值；完成、取消或失败后冻结最后观测值。指标读取失败只使相应值不可用，不影响扫描。进程 I/O 包含后端自身的日志和 SQLite 活动，不等于对扫描目标的读写量，也不表示目标被修改。

## 展示规则

长路径区域允许收缩并显示省略号；大小列保持可见。完整路径仍可通过标题提示、详情和复制路径取得。适用范围包括空间建议卡片、转储分组成员与大文件/目录表；桌面宽度为目标布局。

覆盖问题默认以“扫描完成 · 部分位置未覆盖”表达，不把安全跳过当成程序失败。`ACCESS_DENIED` 显示“权限受限”，`REPARSE_POINT_SKIPPED` 显示“链接/系统重定向未跟随”，`FILE_NOT_FOUND` 显示“扫描期间发生变化”，`PATH_TOO_LONG` 显示“路径限制”，`IO_ERROR` 显示“读取元数据失败”。原始技术代码与计数仍在可展开详情中；后端错误模型未改变。历史快照只保存汇总计数与覆盖状态，旧快照没有各原因明细，页面不会推断或伪造分组数量。

## 已知限制与验证

已保存快照只含 Top-K 文件及目录聚合，不包含全部文件记录或完整错误明细。来源为 snapshot 时不重新访问文件系统。既有 SQLite v2 数据与 M5 候选未改变。自动测试覆盖来源优先级、scope 隔离、重启模拟、目录下钻、Top-K、指标生命周期、覆盖文案与布局契约；真实浏览器视觉验收需在本地浏览器安全策略允许后单独完成。
