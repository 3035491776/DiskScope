# Low-Impact Scan（V0.1 / M1.6）

DiskScope 的目标是在合理时间内完成空间诊断，同时尽量减少对正常使用的干扰。当前唯一模式是 `standard`；扫描只在用户显式发起任务后开始，且同一进程同时最多有一个活动任务、一个枚举 worker。没有后台预扫、并发文件读取或速度模式切换。

## 对目标和硬件的边界

Scanner 使用 `os.scandir` 流式读取名称、大小、修改时间和属性等元数据。不打开文件正文，不计算文件哈希，不预读内容，不修改文件、路径、ACL、属性或时间，也不调用外部 shell 处理目标。目录和 Top-K 结果保留受限的内存记录，不把所有文件内容读入内存。协作式取消在进入目录和处理条目时检查标志；无需杀线程或进程。

默认低并发是明确的取舍：单枚举 worker 避免大量并发 `stat` 对磁盘、缓存和交互应用造成突发负载。扫描不追求磁盘满负载。不得以未测量的“更快”为理由加入线程池、多进程、MFT/USN 或原始磁盘读取；任何性能优化都应先提供可复现 benchmark 及对使用体验的证据。

## 路径和卷策略

当前根目录仅可选受控 `tests/fixtures` 子树，或 M1.5 临时白名单中的精确项目根目录 `D:\Artilius\Codex\Windows-C-clear`。项目扫描按路径组件排除 `.git/`、`.venv/`、`frontend/node_modules/`、`frontend/dist/`、`logs/` 和 `data/`。UNC、设备路径、任意网络盘和其他真实根目录均不准入。入口和每个待枚举目录都重新校验边界；reparse point、junction、symlink 一律不跟随，跨卷候选也直接跳过，不自动转向别的盘符。

独立的整卷安全门 `can_scan_whole_volume()` 在 M1.6 始终返回拒绝。C:\、D:\ 和任意卷根返回专用原因 `WHOLE_VOLUME_SCAN_NOT_APPROVED`。只有未来另行批准准入条件并完成边界与性能验证，才可能修改此门；M1.6 通过不意味着开放 C:\。

## 资源指标口径

Windows 使用当前进程的公开 Win32 计数器，不需要管理员权限。每次扫描记录耗时、文件/秒、进程 CPU 时间增量、进程 read/write transfer bytes 和操作次数的前后差值，以及扫描进度采样到的进程工作集峰值。进程计数器包含本地服务、日志、运行时和其他同进程活动，不等同于目标卷的物理 I/O；采样工作集峰值也不是连续监控的绝对峰值。指标不可可靠读取时返回 `unavailable`，不估算。

`process_write_bytes_before`、`process_write_bytes_after` 和 `delta_write_bytes` 反映**进程范围**写入。少量写入可能来自日志、测试结果、Python 缓存或运行时。Scanner 对**目标目录**写入必须为零，通过源码约束以及扫描前后目录元数据、Git 状态和差异一致性另行验证；不能仅凭进程写入字节数判断目标发生修改。取消后任务的指标冻结，worker 退出，下一任务仍可启动。

`quiet` 和 `fast` 仅是未来讨论的模式名称；当前策略对象拒绝这两种模式，不存在不同并发、优先级或 I/O 行为。后续设计必须先有 benchmark 数据和低干扰验收，再决定是否实现。
