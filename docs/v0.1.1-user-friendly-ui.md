# v0.1.1 — User-Friendly UI Simplification

## 目标

v0.1.1 是面向普通 Windows 用户的纯展示层简化。假设用户只知道“我的 C 盘快满了”，无需理解 DiskScope 的数据模型或安全策略名称，也能找到扫描入口、查看结果、大文件、历史和建议，并理解扫描不会修改文件。

## 简化原则

普通层只回答三个问题：用户正在看什么、为什么值得关注、下一步可以做什么。技术能力不删除，但内部标识、原始枚举和诊断字段统一放入默认折叠的“技术详情”。危险动作保持克制，不使用“一键清理”“电脑垃圾”或“立即加速”等误导表达。

## 术语映射

| 内部概念 | 普通界面 | 展示位置 |
| --- | --- | --- |
| Snapshot | 扫描记录、历史扫描、上次扫描结果 | 普通层 |
| Scope | 扫描位置、扫描范围 | 普通层 |
| Candidate | 建议项、值得关注的文件 | 普通层 |
| Eligibility | 是否符合处理条件、可以处理、暂不符合处理条件 | 普通层 |
| Coverage | 扫描完整度、部分位置未能扫描 | 普通层 |
| Metadata | 文件基本信息 | 普通层 |
| Policy | 安全规则 | 普通层；原始规则在技术详情 |
| Diagnostics | 原因说明、为什么不能处理 | 普通层 |
| RSS | 内存占用 | 普通层；原始字段在技术详情 |
| UUID / ID / reason code / rule version | 原始技术字段 | 技术详情 |

## 页面变化

- 总览优先显示 C 盘容量、上次扫描结果和“扫描 C 盘 / 扫描临时文件”。
- C 盘确认框用一句话说明只读取文件基本信息且不会修改文件；链接、跨卷等细节折叠。
- 扫描状态显示文件、文件夹、时间、速度和内存；进程 I/O、CPU 与原始计数折叠。
- 空间分析以“哪些文件夹占空间”为主线；大文件表只保留名称、位置、大小、修改时间和复制路径。
- 历史页改为“扫描历史”，变化使用新增、减少、变大、变小和没有明显变化。
- 空间建议第一层只显示名称、大小、位置、关注原因、风险和当前状态；判断可靠度与内部规则下沉。
- Settings 只显示版本、数据/日志位置、安全说明和功能边界。
- Probe、Fixture、Project Workspace 和原始审计记录只在开发模式出现。

## 技术详情分层

以下内容继续保留但默认折叠：任务编号、建议项 ID、原始错误码、规则与策略版本、原因码、处理目标、进程读取/写入量、CPU 用时和高级筛选。API 与数据库仍保存原始枚举，不做翻译或 schema 变更。

## 朋友测试计划

使用 fresh DB 的正式 portable 测试包，不让测试者先读 README。测试者应独立识别 C 盘与临时文件入口、理解安全性、完成一项安全扫描、查看空间分析和大文件、进入扫描历史与空间建议，并能解释为什么部分建议项没有处理按钮。反馈问题见 `docs/friend-test-checklist.md`。

## 明确未改变

扫描器架构、扫描范围、数据库 schema v6、M6 清理策略、30 天阈值、风险/判断可靠度语义、逐个建议项 ID 绑定、实时重新验证、Windows 回收站执行和所有 Low-Impact 安全边界均未改变。没有新增后端业务 API、批量处理、文件夹处理、永久删除、MFT、USN 或管理员权限。
